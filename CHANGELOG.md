# Changelog

Notable changes to OptimAI Creative Agents. Each entry names what a builder or creator can now do. Versions follow [Semantic Versioning](https://semver.org/). Portable v1 manifests and saved recipe fields stay compatible across every release listed here.

## Unreleased

### Added

- **Settings forms that build themselves.** `getAgentFormSchema(id)` returns a JSON Schema 2020-12 form for any template, with the exact bounds recipes accept plus a control (`slider`, `stepper`, `color`, `seed`…), step, group (content, look, color, layout, motion) and role for every setting. The role says whether the on-device engine reads a setting, whether it is an older alias (Poster Lab's `format` stands in for `ratio`), or whether it only shapes the brief, so builders can group, hint and order settings without copying field lists. The MCP adapter's tool schemas now come from it, adding hex patterns and alias notes, and `npm run verify` checks every template renders. See [render settings from the form schema](./docs/host-integration.md#render-settings-from-the-form-schema).
- **`@optimai/creative-agents/form-schema`.** `listFormFields` flattens a schema in display order for a renderer, `getAgentFieldRoles` reports each setting's role (also for unreviewed template objects, where a setting nothing reads is `unused`), `plainFormSchema` strips the hints for strict validators, and `recipeFieldSchema` (root export) gives one field's recipe bounds. No dependencies; no recipe or contract change.
- **Every result gets a run record you can return to.** `createRunRecord` gives each result a stable 16-character hash over its template, exact settings, seed, SDK version and a digest of the selected images, so the same run is recognised in every browser and shared records that were edited are refused (`parseRunRecord`). `createRunHistory` keeps a newest-first, de-duplicated run list that collapses a slider drag into one entry, and `canvasLabRecipeValues` turns a run's canvas settings back into recipe values, so **Remix** opens the exact look you made (seed, *camera move*, *frame echoes* and all) instead of the saved defaults. See [run records](./docs/host-integration.md#keep-run-records-and-remix-exact-settings).
- **`@optimai/creative-agents/run-record`.** `digestInputs` digests files or buffers in order (SHA-256, names never count), `canonicalJson` and `hashText` give stable JSON and 64-bit hashes, and `runRecipeValues` splits any settings into portable recipe values and engine-only extras. No dependencies; runs in Node and the browser.
- **Print Shop: riso, halftone and dither looks.** A new canvas template prints a photo on warm paper as a two-ink riso duotone (four ink pairs, blue-noise grain, a touch of misregistration), round halftone dots, or a Floyd–Steinberg, Bayer or blue-noise dither, with a dot size, print strength, ink color and a `seed` that brings back the exact same grain. `output.print` reports what was drawn. The catalog now has 39 templates and the workspace contract is 1.3 (new `canvas:print` operation); existing recipes are unchanged. See [print looks](./docs/runtimes.md#print-looks).
- **`@optimai/creative-agents/print`.** `printPixels` prints any RGBA buffer in place, `separateDuotone` splits a color into two ink coverages, `bayerMatrix` and `blueNoiseMatrix` (void-and-cluster, tileable) give threshold ranks for your own shaders, and `resolvePrint` validates settings. No dependencies; runs in Node and the browser.
- **Glitches you can share and get back exactly.** Glitch Cut now draws from a `seed` stored in the recipe, so the same image, effect, amount and seed give the same bytes on every browser, and a new seed rolls a new arrangement. Its saved *block displacement*, *colour trails* and *frame echoes* treatments now each draw their own look (shifted bands and shuffled blocks, a smeared RGB split, or offset echoes), with an RGB split and scanlines throughout. `seed` is a new optional recipe field (default 1), so existing recipes keep working; `output.glitch` reports the effect and seed drawn. See [seeded glitch](./docs/runtimes.md#seeded-glitch).
- **`@optimai/creative-agents/glitch`.** `glitchPixels` glitches any RGBA buffer in place, `planGlitch` returns the deterministic layout (bands, blocks, split, scanlines, echoes) for a seed and size, `mulberry32` is the generator, and `randomGlitchSeed` rolls a new look. No dependencies; runs in Node and the browser.
- **Transition Lab draws real transitions.** Choose a wipe, an iris (`radial`), a light key (`luma`, the brightest parts of the first shot give way first) or a push instead of the crossfade Reference Blend already makes, scrub `mix` through the eased move, and get a strip of the whole move (`frames`, 5 by default) next to the exported frame. Saved recipes' *match cut*, *camera move*, *light wipe* and *morph* techniques and their *pace* now actually change the picture. `output.transition` and `output.strip` report what was drawn; no new recipe field. See [still transitions](./docs/runtimes.md#still-transitions).
- **`@optimai/creative-agents/transition`.** `composeTransition` composes one frame of a wipe, radial, luma, push or dissolve between any two RGBA buffers, `resolveTransition` validates a style, direction, pace, softness and iris centre, `transitionProgress` eases time and `transitionTimes` spaces frames for a contact sheet. No dependencies; runs in Node and the browser.
- **Image Finish looks the same in every browser.** The noir, warm, cool and punchy finishes are now graded pixel by pixel in OKLab (tone curve, vibrance, white balance, split toning and seeded grain) instead of the browser's canvas filter, which some browsers ignore. The same image, preset, intensity and `seed` give identical bytes, large images stay cancellable, and `output.colorEngine` says which engine ran; `colorEngine: 'css'` keeps the old look. No new recipe field. See [pixel color grade](./docs/runtimes.md#pixel-color-grade).
- **`@optimai/creative-agents/color-grade`.** Build your own looks: `resolveGrade` turns a preset or settings (exposure, contrast, fade, saturation, vibrance, temperature, tint, split tone, grain) into a validated grade, `gradePixels` applies it to any RGBA buffer in place, band by band if you like, and `gradeColor` previews it on a single color. No dependencies; runs in Node and the browser.
- **Film looks and your own `.cube` LUTs in Image Finish.** Pick `film: 'golden' | 'teal-amber' | 'matte'` (three original looks) or pass a `.cube` file's text as `lut` to finish an image with the same LUT you use in your grading tool, applied after the grade and scaled by `intensity`. `output.lut` names the look; no new recipe field. See [LUTs and film looks](./docs/runtimes.md#luts-and-film-looks).
- **`@optimai/creative-agents/lut`.** `parseCubeLut` reads 3D `.cube` files strictly (size up to 65, 16 MiB, errors name the line), `applyLut` applies one to any RGBA buffer with trilinear interpolation (band by band, identity lossless), `createLut` and `formatCubeLut` bake and export your own, `lutColor` previews swatches, and `FILM_LOOKS`/`filmLut` expose the built-in films as data.
- **Titles that stay off the subject.** Poster Lab and Letter Pose now place the title in the calmest part of the image (`position: 'auto'`, the new default) instead of always at the bottom or centre, so a headline no longer covers the car, face or product. Flat images and blank artboards keep the classic layout, `top`, `center` and `bottom` pin it, and Title Frame accepts `position: 'auto'` too. When a title still would not read, it keeps the color you chose and gets the lightest soft scrim that reaches 3:1 contrast, instead of turning white into grey; `scrim: 'off'` keeps the old lightness shift. `output.placement` and `output.scrim` report what was drawn; no new recipe field. See [calm title placement](./docs/runtimes.md#calm-title-placement).
- **`@optimai/creative-agents/text-placement`.** `placeTextBlock` finds the calmest spot for any block on a smart-crop focus map (summed-area table, home bias, breathing room), `regionInterest` scores a rectangle, `fitScrim` returns the lightest black or white scrim that makes an ink pass over given backgrounds, and `chooseTitleInk` combines a small lightness move with a scrim. No dependencies; runs in Node and the browser.
- **Balanced titles.** Poster Lab, Letter Pose and Title Frame now break titles into lines as even as possible, at the fewest lines they need, instead of filling each line first and leaving a lone word at the end. Large titles get tighter tracking and leading and small ones more open spacing, words are no longer split while a smaller size would keep them whole, and long poster titles shrink instead of losing their last lines. `output.lines` reports what was drawn; no new recipe field. See [balanced titles](./docs/runtimes.md#balanced-titles).
- **`@optimai/creative-agents/typeset`.** `fitTitle` finds the largest size at which a title fits a box, `breakLines` breaks text in `balance`, `pretty` or `greedy` mode, `opticalSize` gives tracking and leading for a size, and `canvasMeasure` adapts a 2D context. Works with any measure function; no dependencies.

## 0.5.0 — 2026-10-24

### Added

- **A release in one command.** `npm run release:notes` turns the notes under *Unreleased* into a dated version section and moves the version in `package.json`, the MCP adapter, the README, the release guide and `llms.txt` together. It picks minor or patch from the kind of notes (or takes `major`, `minor`, `patch` or an exact version), refuses an empty or backwards release, and never commits, tags or publishes. See [cut a release](./docs/release-and-feature.md#cut-a-release).
- **`llms.txt` for AI coding agents.** One short file maps every public subpath to its exported functions and types, the guides and all 38 template IDs. It is generated from the shipped declarations (`npm run llms`), and a test fails when it falls behind.
- **Titles that stay readable on any photo.** Poster Lab, Letter Pose and Title Frame check the title color against what is actually behind it. If it would fade into a bright sky or a busy background, only its lightness moves, just enough for 3:1 WCAG contrast, so the hue a creator picked survives. `ink: 'image'` takes the accent color from the photo instead, `ink: 'exact'` keeps the old behaviour, and `output.ink` reports the color drawn. Title Frame's outline now flips to a light halo behind a dark title. No new recipe field. See [readable titles](./docs/runtimes.md#readable-titles-and-image-palettes).
- **`@optimai/creative-agents/color`.** OKLab and OKLCH conversions with gamut mapping, perceptual mixing, WCAG contrast plus a polarity-aware lightness contrast, `pickLegibleColor` for text over one or many backgrounds, and a deterministic OKLab k-means palette (`dominantColors`, `pickAccentColor`, `analyzeImageColors`). No dependencies; runs in Node and the browser.
- **One model setup flow with real sizes.** `createModelSetupController()` in `model-setup` runs idle → checking → downloading (loaded, total) → verifying → ready, with failed and unsupported, around your own reviewed `load` and `check` calls. Creators see "120 MB of 453 MB" instead of a bare percentage, Stop always works, a load already running elsewhere is reused instead of downloaded twice, and late progress from a stopped run can't flip the screen back. `formatBytes`, `describeModelProgress` and `describeModelSetup` turn model metadata into labels such as "453 MB · about 1.7 GB GPU memory", so hosts stop hard-coding sizes. See [setup controller](./docs/runtimes.md#setup-controller-and-sizes).
- **Input policy in the catalog.** `getAgentInputPolicy(id)` returns how many files an agent takes, which types (as an `accept` string) and how large, the browser features it needs or can use (`AGENT_INPUT_NEEDS`: WebGL, WebGPU, Web Audio, camera…), and whether its result is made on the device. Hosts can build upload controls and "runs on this device" filters from the SDK instead of hard-coding limits per agent. See [input policy](./docs/host-integration.md#input-policy).
- **Focus-aware cropping for every canvas cover fit.** Image Grid, resize, Mockup Maker, Pixel Layout, Reference Blend, Transition Lab, Glitch Cut, Poster Lab and Letter Pose now keep an off-centre subject in frame instead of cropping from the middle.
  - Each image is analysed once from a thumbnail of at most 96 pixels. The analysis combines Sobel detail with OKLab color distinctiveness, takes about a millisecond, and uses no model, network or face/skin heuristic.
  - Flat images, matching aspect ratios and environments that cannot read canvas pixels keep the classic centred crop.
  - Pass `crop: 'center'` to opt out.
- **`@optimai/creative-agents/smart-crop`.** `analyzeImageFocus`, `focusCoverRect`, `computeFocusMap` and `findFocusCrop` for your own layouts. The pure steps run in Node. See [focus-aware cropping](./docs/runtimes.md#focus-aware-cropping).
- **`@optimai/creative-agents/verify`: tier-0 checks.** Deterministic local checks an agent can run before paying for a model to judge a draft: WCAG text contrast over the actual background (low percentile, not the mean), text size, text over the subject (using the smart-crop focus map), safe zones, aspect, duration, detector counts, OKLab palette coverage and cut-on-beat timing. Every check returns `{ pass, score, threshold, confidence, costMs }` with higher-is-better scores. See [tier-0 verification](./docs/runtimes.md#tier-0-verification).
- **Steadier, more responsive avatars.** `createFaceRigSmoother()` in `camera-runtime` smooths face rigs with a One-Euro filter: the avatar holds still while the head rests and follows fast turns and blinks without the lag of the fixed 80 ms moving average. In the bundled tests it shows a third less jitter at rest and under half the lag on a quick head turn. `smoothFaceRig` keeps working.
- **`@optimai/creative-agents/landmark-filter`.** `createOneEuroFilter` and `createOneEuroVectorFilter` (with a `stride` for x,y or x,y,z points) to smooth your own face, hand or pose landmarks. Runs in Node and the browser. See [landmark smoothing](./docs/runtimes.md#landmark-smoothing).
- **Sound Canvas can pulse on the beat.** `renderMusicReactiveFrame` accepts an optional `pulse` (0–1) that swells each look's geometry on the beat. It never changes colour or brightness, and reduced motion ignores it.
- **`@optimai/creative-agents/beat-tracker`.** `createBeatTracker()` finds onsets, tempo (BPM with a confidence) and a phase-locked beat clock from the same analyser bytes, on the device and in Node. Its visual pulse has a built-in WCAG 2.3.1 flash limiter (at most three flashes a second, which cannot be raised) and a reduced-motion mode that keeps beats but never pulses. `estimateTempo`, `logBandSpectrum`, `spectralFlux`, `createFlashLimiter` and `prefersReducedMotion` are exported too. See [beat sync](./docs/MUSIC-MOTION.md#beat-sync-beat-tracker).
- **Documentation guard.** `test/docs.test.mjs` checks that the README and guides state the shipped template count, capability groups and package version.

### Fixed

- The README, catalog, quickstart and MCP guides now describe the shipped catalog: **38 templates** (10 canvas, 3 vision, 5 writing, 6 interactive, 14 guided) and version 0.4.0. The catalog now lists Sound Canvas and Frame Sculpture.
- The MCP adapter reports the package version in `serverInfo` instead of a hard-coded `0.3.0`.

## 0.4.0 — 2026-10-14
